| 1 | Medium | Change detection compares only size + mtime (`fsops/scan.go:137`): a workload can rewrite a jar in place with the same size and restore the mtime, so hash and parsed entries may describe different contents without `IO_ERROR` (probe executed: same-size replacement with restored mtime → `OK`) | Fixed: the file identity (`fsops/scanid_*.go`) is device + inode + size + mtime + inode change time (Linux `st_ctim`, BSD `st_ctimespec`; set by every write/truncate/chmod/utimes, not settable by an unprivileged process), taken once the file is open and re-checked after the whole-file hash and after the jar parse, for `fs.hash` and `jar.readEntries`. A file changed < 20 ms ago is re-examined after a short wait first, so a coarse kernel timestamp tick cannot hide a change; one that keeps changing → `IO_ERROR`. No snapshot copy needed: every pass is bracketed by identity checks. Windows (dev only) keeps size + mtime + file index. Tests: `TestScanSameSizeRewriteWithRestoredMtime` (rewrite between hash and parse, before the parse, and during `fs.hash` → `IO_ERROR`; control → hash and entry of the same bytes), `TestDigestDetectsChangesWhileReading` (same-size case), `TestSettleWaitAndContinuousChanges`, `TestSettledID` — Linux path; each fails with ctime removed from the identity |
| 2 | Medium | No command-wide read budget for `jar.readEntries`: `maxJarBytes` applies per path, so 256 × 2 GiB with whole-file hashes = up to 512 GiB of reads in one command; `maxTotalBytes` only bounds returned content | Fixed: contract `maxReadBytes` (default 8 GiB, max 64 GiB) in the Go validator; every byte read is counted (whole-file hash, end-record search, central directory, local headers, entry data via a metered `ReaderAt`). After the first jar (always processed) a jar whose whole-file hash would not fit is `BUDGET_EXCEEDED` before any byte of it is read, and a parse that would read past the budget stops there → `BUDGET_EXCEEDED`; every later jar too. Tests: `TestReadJarEntriesReadBudget` (with and without hashes: budget 1 / 2×cost−1 / 2×cost / 3×cost / default, mid-parse stop never reads past the budget, size pre-check reads nothing), `TestExtensionScanSchemas` (maxReadBytes bounds + default), `TestExtensionScanFixtures` (default on the fixture) |
| 3 | Low | Escaping symlinks report `NOT_REGULAR` instead of `PATH_FORBIDDEN` (`fsops/scan.go:37-46` only keeps denylist errors from `checkDeny`), unlike `fs.read` | Fixed: symlink resolution marks sandbox escapes (absolute target, `..` above the root; `fsops/deny.go` `escapeError`, unwrapping to the unchanged `PATH_FORBIDDEN` error so other commands are unaffected); scans map them to `PATH_FORBIDDEN` (no `reason: "denylist"`), with or without a denylist, while in-root symlinks (incl. dangling and loops) stay `NOT_REGULAR`. Tests: `TestHashPerFileOutcomes` (absolute file/dir links, `../..` parent link, in-root chain into an escaping link → `PATH_FORBIDDEN`; in-root file/parent/up/dangling/loop links → `NOT_REGULAR`; same mapping for `jar.readEntries` and under a denylist) — Linux path |

Test gaps called out: same-size rewrite with restored mtime, command-wide read limit, escaping-symlink error mapping.
